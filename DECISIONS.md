# DECISIONS

## 2026-10-24
- **D1 Python package name `clarity_tse`** (not `clarity`): pyclarity (used for HASPI/HASQI/MSBG/NAL-R reference implementations) owns the import name `clarity`. The prompt's layout (`dsp/`, `embed/`, `models/` ...) lives under `clarity_tse/`; `rt/`, `android/`, `study/`, `bench/`, `paper/`, `results/` stay at repo root.
- **D2 Compute rung: "Fallback 1" (smaller accelerator).** Apple M5 Pro MPS. Models are kept small (<~2 M params) and training budgets short; all model results labelled *reduced-scale*.
- **D3 Data rung: "Fallback 1".** LibriSpeech (CC BY 4.0) speech + ESC-50 environmental noise + synthetic babble/music-like noise + pyroomacoustics rooms. Clarity Challenge data is gated and not present.
- **D4 Sample rate 16 kHz** for all models/metrics (PESQ-WB, ESTOI, DNSMOS operate at 16 kHz; HASPI resamples internally to 24 kHz).
- **D5 Multi-mic rung: "Fallback 1" — simulated 2-mic binaural earbud pair** (ear spacing 0.18 m, free-field mics, no head-shadow HRTF) rendered with pyroomacoustics image-source RIRs. No HRTF dataset with a clean licence was integrated; limitation documented (no ILD from head shadow; ITD/phase cues only).
- **D6 Head-orientation rung: "Fallback 1" — simulated yaw trajectories**; head rotation renders by crossfading RIR sets computed on a yaw grid.
- **D7 Real-time rung: "Fallback 1" — desktop C++ engine** (CoreAudio output clock on macOS, file-injected input) + offline streaming simulation with measured per-hop compute. Android app is built but on-device numbers are unavailable without a device.
- **D8 Bluetooth latency: "Fallback 1" — published ranges, labelled `estimated`.**
- **D9 Speaker splits:** train speakers = train-clean-100; val = dev-clean; test = test-clean. LibriSpeech subsets are speaker-disjoint by construction. ESC-50 folds 1–3 train, 4 val, 5 test; room parameters drawn from disjoint seeded RNG streams and disjoint RT60 sub-ranges are not used (same distribution, different draws) — documented as a threat.
- **D10 Speaker embedder:** frozen pretrained SpeechBrain ECAPA-TDNN (VoxCeleb; Apache-2.0) instead of training an "ECAPA-style" model on 251 LibriSpeech speakers, which would generalise poorly. Training conditioning uses embeddings of the 16 longest utterances per train speaker (cut to 10 s, matching test-time 10 s enrollment). A deterministic MFCC-statistics embedder is used only on CI fixtures.
- **D11 Pre-rendered training pool:** the host is shared and heavily loaded (BLOCKERS B8). Rendering mixtures on the fly would starve the GPU, so 40k 4-s binaural mixtures (80 shards) are rendered once from the 4000-geometry RIR bank and reused by all runs. Enrollment embeddings, "enrolled-but-absent" examples (embedding of a speaker not in the mix, reference = silence), voice/direction dropout, DOA noise (σ = 5°) and ±10 dB level are applied at load time.
- **D12 Reduced training budget:** measured about 0.7–0.8 s per step (batch 16, 4 s, 10 ms hop) on the contended MPS GPU. Sweep: 8k steps per run; 3 seeds only at the operating point(s); the 2 ms and 5 ms models are initialised from the 10 ms model (the "latency-aware curriculum"), with a from-scratch 2 ms run as the curriculum ablation. All model numbers are reduced-scale.
- **D13 Latency definition used for the budget:** algorithmic latency = synthesis window (2·hop) + lookahead; the ≤20 ms constraint is checked as algorithmic + measured p99 per-hop compute. NAL-R baseline delay (110 samples = 6.9 ms, linear-phase FIR) is reported, and compensated before scoring.
- **D14 On-device target selection:** the full τ policy (DOA tracking + IMU + voice similarity) is implemented and evaluated in Python (M4). The Android app ships the two user-facing modes with a simplified policy: "facing" = straight-ahead direction prior, "voice" = enrolled embedding with no direction. Porting the tracker to C++ is future work.

## 2026-10-25
- **D15 Training budget revised:** measured 0.55 s/step (b16) and 0.8 s/step (teacher) at load ≈ 60; two concurrent MPS runs give 1.47× the throughput of one (each 0.75 s/step). The sweep runs 2 lanes (`bench/train_sweep.sh`), 6000 steps per run (teacher 8000; curriculum runs 3000). Supersedes the 8k figure in D12.
- **D16 Operating point = 16 ms budget (hop 128 samples, 8 ms).** The constraint is algorithmic + compute ≤ 20 ms; a 20 ms algorithmic model cannot meet it once any compute is added, so the largest admissible budget on the grid is 16 ms. 3 seeds and all ablations are trained at b16 (also the cheapest per step); b10 also gets 3 seeds as a second reference point. The 20 and 40 ms models are reported to complete the curve but are marked as outside the budget.
- **D17 Curriculum layout:** b2 and b5 are initialised from b10_s0 with half the steps (matching D12's intent); `b2_scratch_s0` (full steps, from scratch) is the curriculum ablation. Previous gen/ configs (b2_curr, b2/b5/b20/b40 extra seeds, ablations at b10) were replaced.
- **D18 ECAPA on device:** SpeechBrain's Fbank uses complex `torch.stft`, which does not export; `bench/export_ecapa.py` swaps in an equivalent strided-conv real DFT. ONNX vs PyTorch embedding cosine = 1.000000 on 10 s and 15 s inputs.
- **D19 Android native ORT:** onnxruntime-android ships no prefab; Gradle unpacks the AAR's headers/.so for the JNI engine (`extractOrt`). The user-level Gradle init script adds a repository, so settings use `PREFER_SETTINGS`.
- **D20 Real-time thread class on desktop:** `clarity_bench --rt` puts the processing thread in the Mach time-constraint class (period = hop, budget = hop/2), matching what CoreAudio gives its IO thread, so benchmark tails reflect an RT audio thread rather than a default-priority thread on a shared host.
